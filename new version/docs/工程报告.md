# SurgReview 工程报告

> 面向腹腔镜胆囊切除术（LC, Laparoscopic Cholecystectomy）的手术视频分析、教学辅助与阶段识别平台。
> 本文档基于当前 `new version/` 代码状态编写，覆盖项目路径、技术栈、前后端结构、接口设计与核心流程。

---

## 1. 项目概述

SurgReview（原 SurgInsight / CholecInsight）是一个前后端分离的 Web 原型，聚焦外科手术视频的智能分析，目标场景为：

- **外科教学**：通过关键步骤时间线辅助手术过程讲解
- **病例复盘**：阶段识别与标注，便于术后回顾
- **流程分析**：对关键步骤（术前准备、胆囊三角解剖、夹闭切断、胆囊剥离、胆囊装袋、清理止血、胆囊牵引）自动识别

当前版本已具备：用户注册登录、视频项目本地管理、关键步骤 AI 分析（7 阶段识别）、MobileSAM 交互式分割、AI 智能问答、社区项目分享与互动（帖子/评论/点赞/收藏/关注/下载/反馈）。

## 4. 后端接口

统一前缀与鉴权：除 `GET /health` 与注册/登录外，所有接口要求请求头 `Authorization: Bearer <token>`（7 天有效期）。

### 4.1 系统与健康检查

| 方法 | 路径 | 说明 | 响应要点 |
|------|------|------|----------|
| GET | `/health` | 健康检查 | `{status, model_loaded, sam_model_loaded, message}` |

### 4.2 认证（`/api/auth`）

| 方法 | 路径 | 说明 | 请求要点 | 响应要点 |
|------|------|------|----------|----------|
| POST | `/api/auth/register` | 注册 | `{username, email, password}`（密码 8-128 位含字母数字） | `{token, user}` |
| POST | `/api/auth/login` | 登录 | `{identifier, password}`（用户名或邮箱） | `{token, user}` |
| POST | `/api/auth/logout` | 登出（撤销令牌） | Bearer token | `{message}` |
| GET | `/api/auth/me` | 当前用户信息 | Bearer token | `user` |

安全实现：PBKDF2-SHA256（200k 迭代 + 随机盐）存哈希；不透明随机令牌存 `sessions` 表，登出即删除，支持吊销。

### 4.3 关键步骤分析（`/api/phase`）

| 方法 | 路径 | 说明 | 请求要点 | 响应要点 |
|------|------|------|----------|----------|
| POST | `/api/phase/jobs` | 创建分析任务 | multipart `file` + `sample_seconds`（默认 2.0） | `{jobId, status: queued, progress, ...}` |
| GET | `/api/phase/jobs/{job_id}` | 查询任务状态/结果 | — | `{jobId, status, stage, progress, result, ...}` |
| PUT | `/api/phase/jobs/{job_id}/annotations` | 保存人工标注 | `{segments: [{phaseKey, phaseLabel, startSeconds, endSeconds, edited, source}]}` | 更新后的 job |

任务状态机：`queued → running → completed | failed`。分析在后台线程执行，前端轮询获取进度与结果；结果包含 `steps[]`（时间线、置信度）与 `meta`（时长、采样信息）。

### 4.4 图像分割（`/api/segment`）

| 方法 | 路径 | 说明 | 请求要点 | 响应要点 |
|------|------|------|----------|----------|
| POST | `/api/segment` | MobileSAM 点提示分割 | `{image: base64, points: [{x, y, label}], frame_width?, frame_height?}` | `{status, mask(b64), ...}` |

### 4.5 AI 问答（`/api/chat`）

| 方法 | 路径 | 说明 | 请求要点 | 响应要点 |
|------|------|------|----------|----------|
| POST | `/api/chat` | 豆包大模型问答 | `{question, context?}` | `{answer}` |

后端 `llm.py` 内置两套提示词：分析页 AI 助手（英文系统提示）与社区项目问答（中文系统提示，基于共享项目数据回答）。

### 4.6 社区（`/api/community`）

| 方法 | 路径 | 说明 |
|------|------|------|

## 5. 前端结构

### 5.1 路由（`src/router/index.js`，History 模式 + 登录守卫）

| 路径 | 页面 | 说明 |
|------|------|------|
| `/` | Splash | 启动页（需登录） |
| `/login` | Login | 登录/注册 |
| `/home` | Home | 项目列表：创建/查看/删除/复制、上传视频、分享入口 |
| `/analysis` | Analysis | 分析页：视频播放、阶段分析任务、时间线标注、SAM 分割、AI 问答、报告导出 |
| `/community` | Community | 社区开源广场：项目/帖子浏览 |
| `/community/projects/:id` | ProjectDetail | 社区项目详情、QA 问答、下载 |
| `/community/posts/:id` | PostDetail | 帖子详情与评论 |
| `/community/mine` | MyCommunity | 我的项目/帖子/评论/收藏/点赞 |
| `/community/users/:id` | AuthorProfile | 作者主页（关注/粉丝） |
| `/community/downloads` | Downloads | 我的下载 |
| `/community/feedback` | Feedback | 意见反馈 |

守卫逻辑：未登录访问 `requiresAuth` 页面重定向 `/login`；已登录访问 `/login` 重定向 `/home`。

### 5.2 本地数据层

| 存储 | 键名（当前） | 数据 | 说明 |
|------|--------------|------|------|
| localStorage | `surgreview-projects` | 项目列表（含阶段分析结果） | 模块加载时自动迁移旧键 `surginsight-projects` |
| sessionStorage | `surgreview-active-project` | 当前激活项目 | 同上迁移 |
| localStorage | `surgreview-share-map` | 本地项目 id → 社区项目 id | 驱动"已分享"徽标 |
| IndexedDB | `surgreview-media`（store: videos） | 项目上传的视频文件（按 projectId） | 启动时自动迁移旧库 `surginsight-media` |
| localStorage | `surgreview-auth-token` 等 | 登录令牌 / 用户信息 | `lib/auth.js` 管理 |

### 5.3 关键交互流程

1. **关键步骤分析**：`Analysis.vue` 上传视频 → `createPhaseAnalysisJob` → 轮询 `getPhaseAnalysisJob` → 完成后渲染时间线/置信度/阶段分布 → 结果随项目存 localStorage；进度状态经 `phaseAnalysisStore.js` 同步到项目。
2. **分享到社区**：`Home.vue` 将本地项目（元信息 + 阶段数据）POST 到 `/api/community/projects` → 记录 `share-map` → 可在社区广场查看、QA、下载。
3. **报告导出**：`Analysis.vue` 生成可打印 HTML 报告（`buildReportPdfHtml`），社区项目支持 `/export` JSON 导出。

- Node.js 18+ / npm 9+
- Python 3.10+（实测 3.12）

## 8. 当前边界与注意事项

- **无独立数据库服务**：用户/社区数据在本地 SQLite；项目数据在浏览器本地存储，清空浏览器数据会丢失项目。
- **模型非开箱即用**：权重需从网盘手动放入 `backend/pretrained_weights/`；模型懒加载，首次提交分析任务时初始化。
- **网络依赖**：AI 问答依赖火山引擎 Ark 外网可达；本机直连 GitHub 被墙，push 需经 `ghfast.top` 代理。
- **并发模型**：后端为多线程任务模型（`threading` + 锁），未使用异步任务队列，高并发场景需扩展。
- **安全提示**：`backend/llm.py` 内嵌了默认 Ark API Key（明文），正式部署应改用环境变量；`users.db` 含测试账号哈希，随仓库提交属团队约定，生产环境应更换存储方案。
